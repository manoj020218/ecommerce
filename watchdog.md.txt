# Codex Task: Build Standalone E-commerce Order Pipeline Watchdog

## Product Goal

Build a standalone SaaS-ready module named **Commerce Watchdog**.

This module must monitor an e-commerce website from the moment a buyer visits a product page until the buyer completes checkout successfully. It must detect technical/business failures before the buyer raises a ticket.

The system should work first on our own e-commerce site, but code architecture must be designed as a reusable standalone product/plugin for any e-commerce website.

## Core Intention

The module should answer:

1. Where did the buyer get stuck?
2. What exactly failed?
3. Was it frontend, backend, payment gateway, database, stock, invoice, order history, or webhook issue?
4. How many users are affected?
5. What action should admin take?
6. Can the system auto-retry or auto-create an internal ticket?

## Tech Stack

Use:

* React + TypeScript for admin dashboard
* Node.js + TypeScript backend
* MongoDB
* Express or Fastify
* PNPM
* REST API first
* Webhook-ready architecture
* Plugin/SDK approach for frontend website
* Modular files, each component preferably under 200 lines
* Unit tests and integration tests required

## Main Modules

### 1. Frontend Web SDK

Create a lightweight JavaScript/TypeScript SDK that any e-commerce website can add.

Example use:

```html
<script src="https://cdn.example.com/commerce-watchdog.js"></script>
<script>
  CommerceWatchdog.init({
    projectId: "STORE_ID",
    apiKey: "PUBLIC_KEY",
    environment: "production"
  });
</script>
```

SDK must track:

* Product page viewed
* Add to cart clicked
* Add to cart success/failure
* Buy now clicked
* Cart opened
* Checkout started
* Address form submitted
* Coupon applied
* Shipping calculated
* Payment initiated
* Payment redirected
* Payment success callback
* Payment failure callback
* Order created
* Invoice generated
* Order confirmation shown
* Order history visible

SDK must also capture:

* sessionId
* anonymous visitorId
* userId if logged in
* cartId
* productId
* orderId
* paymentAttemptId
* browser
* device
* URL
* frontend error
* API response status
* timeout
* page load performance
* click event timestamp

Do not collect card number, CVV, UPI PIN, password, or sensitive payment details.

Every event must be stored as immutable timeline data.

## 3. Order Pipeline State Machine

Create clear state machine:

```text
PRODUCT_VIEWED
ADD_TO_CART_CLICKED
ADD_TO_CART_SUCCESS
CART_VIEWED
CHECKOUT_STARTED
ADDRESS_SUBMITTED
SHIPPING_CALCULATED
PAYMENT_INITIATED
PAYMENT_PENDING
PAYMENT_SUCCESS
PAYMENT_FAILED
ORDER_CREATED
ORDER_CONFIRMED
INVOICE_GENERATED
ORDER_HISTORY_VISIBLE
COMPLETED
```

Detect abnormal states:

```text
ADD_TO_CART_CLICKED but no ADD_TO_CART_SUCCESS within 5 sec
CHECKOUT_STARTED but no ADDRESS_SUBMITTED within expected time
PAYMENT_SUCCESS but ORDER_CREATED missing
ORDER_CREATED but INVOICE_GENERATED failed
ORDER_CONFIRMED but order not visible in history
Payment webhook received but order status not updated
API error rate increased
Same product failing add-to-cart repeatedly
Same payment gateway timeout repeated
```

## 4. Watchdog Rule Engine

Build configurable rule engine.

Example rules:

```json
{
  "ruleCode": "PAYMENT_SUCCESS_ORDER_MISSING",
  "severity": "critical",
  "condition": "PAYMENT_SUCCESS received but ORDER_CREATED missing within 60 seconds",
  "recommendation": "Check payment webhook handler, order creation API, database transaction, and payment reconciliation job."

```

Severity levels:

```text

```

## 9. Cause and Recommended Action Engine

For each incident, generate practical cause and action.

Examples:

### Add to Cart Failed

Cause:

```text
Cart API returned 500 or timeout. Product may be out of stock, pricing mismatch, or cart service is down.
```

Recommended action:

```text
Check product stock, product price rule, cart API logs, and recent deployment.
```

### Payment Success but Order Missing

Cause:

```text
Payment gateway marked payment as successful, but local order creation did not complete.
```

Recommended action:

```text
Run payment reconciliation, retry order creation, check webhook logs, and contact buyer before refund delay.
```

### Invoice Download Failed

Cause:

```text
Order exists but invoice PDF generation failed.
```

Recommended action:

```text
Check invoice template, GST/tax data, PDF service, and storage permission.
```
